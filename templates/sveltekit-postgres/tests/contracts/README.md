# Contract tests

Contract tests live in this directory. They are **generated by `openexec run`** as
part of implementing a feature, and must hit a real Postgres instance — not a mock.

## Layout

```
tests/contracts/<feature>/<operation>.test.ts
```

For example, a `users` feature with a `signup` operation lives at:

```
tests/contracts/users/signup.test.ts
```

## Runtime

Contract tests use the `contract` Vitest project (see `vitest.config.ts`). A
Postgres testcontainer is started once before the suite and torn down after via
`tests/setup.ts`. Individual tests can use `resetDb()` from `tests/helpers.ts` to
reset state between tests.

Run them with:

```
npm run test:contract
```

## Rules

- No mocks. Every call goes through the real REST handlers against a real DB.
- Every mutating operation must assert on both the API response AND the DB state.
- Fixtures must be created via helpers (see `tests/helpers.ts`) so they can be
  reused by bot users.
